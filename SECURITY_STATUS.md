# SHADVERSE JARVIS security status

| Boundary | Evidence and current scope |
| --- | --- |
| SHADVERSE authentication | Isolated auth checks cover registration-code activation, session expiry and revocation, CSRF, rate limiting, and a single browser login. Phase A staging acceptance is pending. |
| OpenClaw | SHADVERSE connects to its configured Creator Gateway on IPv4 loopback. The token file is owner-only. Browser requests cannot supply provider credentials, backend overrides, or OpenClaw headers. |
| Model orchestration | Managed routing is opt-in with owner-only metadata. It requires verified free routes and denies all paid or unknown-cost dispatch. Actual no-cost eligibility and no upstream paid fallback require authorized staging verification. |
| Usage | Model attempt accounting excludes prompts, replies and tokens used as credentials. Ambiguous requests retain reservations. An output cap passed to OpenResponses remains provider-dependent. |
| Persian voice | Local-only recognition and synthesis are required at the browser boundary. Only the transcript reaches the existing Creator Gateway. Browser fixtures verified disconnect propagation. Native device and provider cancellation remain pending. |
| Conversation history | Completed text and voice pairs are stored in private SQLite and paged by authenticated Creator account. Failed and canceled requests are excluded. The configured Gateway credential is rejected in submitted prompts and replies. |
| Ranked memory | Eligibility is private by default. A local preview shows exact candidates before sharing. The server reranks and matches the ordered source IDs, kinds and revisions on Send, and admits only the current owner and selected scope. Prior questions require a separate opt-in. |
| Explicit memory | Saved notes are scoped to the authenticated account for reads, export and mutations. There is no automatic capture. One exact personal or project note revision may be sent only through explicit Creator chat selection. The server checks owner, scope and revision, and uses a separate Gateway session for that turn. OpenClaw may retain the note under its own storage policy. Store the production state on protected storage and scope access to exports. |
| Document processing | Owned inputs only. Optional in-memory worker receives bounded input and has capped time, memory, output and process count. Macro and unsupported embedded packages are denied. No document inference on the privileged Creator Gateway. |
| Private text files | Account-scoped SQLite BLOB storage, bounded UTF-8 input, CSRF on writes and attachment-only download. Previews are literal text. Uploaded content stays out of the privileged Gateway until a restricted file-inference boundary is verified. |
| Local artifact exports | Printable HTML escapes user text and blocks script and network access with a document CSP. CSV cells are quoted and spreadsheet formula prefixes are neutralized. The browser creates these files from explicit workspace data. |
| Creator Bootstrap | One account-bound private package with optimistic revision checks, approved project mapping and explicit preview consent. Rejected known credentials and schema overflow. No private facts or package data in source control. |
| Device inventory | Dedicated loopback profile with a fixed read-only CLI surface. Exclusive account grant plus target consent. Expiry and revocation are rechecked after upstream I/O. Browser receives a minimal status projection. |
| Composer action review | Fixed grammar produces bounded local actions or a browser link. Confirmations are single-use, session-scoped and expire in two minutes. Website navigation requires the user to follow the link and produces no server request. |
| Workspace actions | The allowlisted actions require CSRF for project creation and task creation or completion. Queries and mutations enforce account ownership. The task action also scopes every task ID to its project. The registry accepts no command, destination, caller-supplied owner or model-generated execution. |
| Restricted research | Optional separate loopback credential and pinned configuration. Fixed OpenClaw search/read calls, server-selected citations, account-scoped expiry, no privileged chat injection. Effective policy and official zero-cost route are pending. |
| Workspace integration grants | The connector grants one account-owned, 15-minute read scope for that account’s project count. Scope and expiry are enforced in the same statement as usage accounting. Revocation blocks future reads. There is no third-party request or credential. |
| Background workflows | Scheduler executes only account-scoped project counts and open-task checks. It stores results and optional in-app notices transactionally. Schedule, pause, cancel, acknowledge and clear controls use the authenticated account and CSRF. No model, credentials, system command or external operation is available to jobs. |
| Task reminders | Signed-in account and project scope apply to every reminder creation, cancellation or due list. Reminders use bounded timestamps and passive Workspace display. No background job or external dispatch is enabled. |
| Browser visual capture | Creator starts camera or sharing explicitly, screens are previewed before submission, and one selected frame is held in browser memory. Navigation, stop, logout, timeout and document hiding close media. Browser uploads normalize JPEG, PNG and WebP to bounded PNG. |
| Restricted vision | Default-deny admission uses a separate loopback port, credential, deny-all configuration and operator evidence. The product validates normalized PNG, strips ancillary metadata, keeps only bounded session metadata and never routes images to the legacy Creator Gateway. Effective runtime policy and provider cost remain live gates. Explicit Stop ends the upstream request and releases the connected HTTP response. Unknown usage remains reserved. The preflight performs only anonymous and authenticated empty requests to approved loopback endpoints. |
| Commercial isolation | DISABLED FOR SECURITY. No commercial account can route through the Creator Gateway. Independent runtime, storage and credential isolation requires live acceptance before activation. |
| Provider grants and billing | Provider configuration requires official verified grants. No paid services or real billing are authorized. |
| Production | Deployment, public Gateway access, production DB changes and infrastructure changes remain gated. |
